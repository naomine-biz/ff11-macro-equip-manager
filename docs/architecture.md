# 責務と参照状態

## 責務境界

| 部品 | 責務 |
|---|---|
| ui / presentation | 閲覧、状態表示、変更案の確認 |
| application | 読込・補正・保存・復元のユースケース |
| domain | マクロ、装備セット、枠、所持品、参照状態 |
| references / fixes | 純粋な状態判定と補正計画。ファイルI/Oなし |
| adapters / codecs / dictionaries / icons | 原本読取、バイナリ解析、文字列・アイコンの解決 |
| saving | 保存前再検証、限定的なバイト変更、バックアップ、置換、復元 |
| store | アプリ専用の表示名。ゲーム内へメタデータを書かない |

## 判定

「一致」は同じキャラの収納ID・内部位置・種類IDが一致すること。内部位置は収納内の保存スロットを、種類IDはアイテムの種類を表す。

保存位置が異なり、全17収納を取得できていて種類IDが一意ならFix可能。収納家具・金庫も対象とする（外見固定用途を含む）。候補複数・候補なし・取得不足・不正な位置は保留とする。

ゲームの代替検索により、保存位置が異なっていても装備できる場合がある。照合結果は読み取ったローカルのインベントリ情報に基づく。

## 保存の前提

FF11・PlayOnline終了時のみ。対象ファイルと全収納をSHA-256で再確認し、ドメインで候補を再計算する。収納と位置のバイトだけを変更しMD5を更新。バックアップをflush/fsyncして検証し、同一ディレクトリの一時ファイルから置換する。保存先を全バイト比較し再デコードする。

対象ハンドル解放から置換までの短い競合窓があるため、保存中はゲームや別のエディタを終了した状態に保つ。保存の単位は1ファイルとし、障害時の復旧にはバックアップを使う。復元は保存後ハッシュが一致する場合のみ行う。

## マクロと装備セットの参照

macro_linksは読み取り専用のドメインクエリ。application経由でUIに結果を渡す。キャラ内の各マクロ行の先頭にある/equipset・/lockstylesetと1〜200の固定番号を解析する。定型文の解決済みコマンドも扱う。参照番号はコマンド直後から抽出し、末尾のecho、wait、付加テキストから独立して判定する。マクロ構文の妥当性検証は別の責務とする。チャットへの記述、動的番号、範囲外番号は解析対象から除外する。

全16枠がkeepのセットを空とする。remove指定のセットは動作あり、未知動作・未取得セットは要確認として扱う。空判定には16枠の動作を使用する。未参照は読み取れたマクロの対応コマンドから参照がないことを意味し、手入力や外部スクリプトでの利用は対象外。空のセットは未参照一覧とセット側の参照表示から除外する。マクロ側の空セット参照通知は維持する。左の装備セット一覧では空セットの文字をグレーで表示する。

UIはマクロカードと行詳細で空セット参照を通知し、装備セット一覧にマクロ参照なしを表示する。専用の確認画面から対象へ移動できる。この確認機能は読み取り専用とする。

装備セット選択時、右パネルに参照元マクロのブック・パレット・Ctrl/Altキー番号・マクロ名・行番号・コマンドを表示する。空セットでは参照表示を省略する。

マクロ画面のナビゲーションはブック名を親、パレットを子とするツリー。ブックは1つずつ開くアコーディオン表示とし、別のブックを開くと前のブックを閉じる。初期表示と参照一覧からの移動では、対象パレットのブックを開く。全マクロの名前と全行が空のパレットはグレー表示する。全パレットが空のブックもグレー表示する。名前のあるマクロや行に内容のあるマクロは使用中として表示する。

## 編集バッファと責務

| 部品 | 責務 |
|---|---|
| macro_inventory | /equipの解析、候補照合、収納番号の置換案。純粋なドメイン処理 |
| editing | 読込時の基準データと編集データ、変更前後を持つ操作、Undo／Redo。メモリ内で完結 |
| edit_application | ドメインへの委譲、古いFix案の再検証、作業保存成功後の編集状態の公開 |
| draft_store | 作業ファイルの直列化、原本ハッシュの照合、排他・一時ファイル・置換 |
| UI | 状態の表示、入力、差分プレビュー、操作の依頼 |

1つの編集セッションはインストール先の全キャラを扱う。読み取りスナップショットをコピーして基準データと編集データを作り、画面と参照判定は編集データを見る。個別編集・一括Fix・将来のカスケード更新をそれぞれ1操作とする。操作中の1箇所でも前提が崩れていたら、操作全体を中止する。新しい操作は現在位置より先のRedo履歴を置き換える。

装備セットFixも同じ履歴に記録する。Undo／Redoはキャラ横断の操作順に行う。変更のない編集は履歴に追加しない。未変更のTextはraw_hexを保持し、変更したTextはdraft状態で保持する。ゲーム形式への文字数・エンコード・定型文変換の検証は将来の保存アダプターで実装する。

作業はバージョン付きJSONへ自動保存する。基準データのファイルパスとSHA-256、全履歴、現在位置を保存する。復元時は読込元との一致を確認して履歴を再適用する。取得元が変化した場合や履歴の破損時は作業再開を保留し、既存作業ファイルを保持する。現段階の解決導線は旧作業の保管と、新しい基準データからの編集開始。差分の選択的な引き継ぎは今後の機能とする。

作業保存は排他ロック・変更検知・一時ファイルのflush/fsync・置換で行う。保存失敗時はメモリ上の編集状態も維持する。複数起動からの上書きを検出する。プロセス強制終了によってlockが残った場合は、全アプリ終了後に該当lockを除去して再開する。

現在のGUIからはアプリ専用の作業ファイルへ保存する。ゲームへの保存・復元ボタンは外す。既存CLIのゲーム保存機能は独立して保持する。将来ゲームへ保存した後のUndoも編集バッファへの操作として扱い、ゲームへの反映時には改めて保存プレビュー・競合検証・バックアップを行う。

## マクロとインベントリの参照

/equipの部位・装備名・任意の収納番号を解析する。引用符、解決済み定型文、末尾waitを扱う。収納番号0はマイバッグ、1は内部収納ID8、2〜8は内部収納ID10〜16へ変換する。表示名の完全一致で全17収納の候補を検索する。

| 状態 | 条件・対応 |
|---|---|
| 一致 | 指定収納内に候補1つ |
| 収納未指定・Fix可能 | 全収納で候補1つ、装備用収納にある。番号を追加 |
| 収納違い・Fix可能 | 指定収納に候補がなく、全収納で候補1つ、装備用収納にある。番号を変更 |
| 収納未指定・候補複数 | 番号指定なしで複数 |
| 同一収納に候補複数 | 指定収納に複数。使い分けには収納を分ける |
| 別の収納に候補複数 | 指定収納に候補がなく、別の収納に複数 |
| 候補なし | 全収納に該当名なし |
| 装備用収納への移動が必要 | 唯一の候補が金庫などにある |
| 取得不足 | 収納の読取不足、重複位置、不正な位置 |
| 記述を確認 | 部位・収納番号などの構文を解析できない |

部位だけの/equipは装備を外す操作。候補複数は状態と候補位置を示す。収納番号Fixは数字の範囲だけを置換し、未指定なら装備名の直後に追加する。その他の文字列を保持する。適用時に候補を再計算し、プレビューと一致することを確認する。

マクロ・インベントリ参照一覧は初期表示をFix可能な行に絞る。「すべての参照」で全状態へ切り替える。Fix案のないマクロのFixボタンは無効にする。
