# 責務と参照状態

## 責務境界

| 部品 | 責務 |
|---|---|
| ui / presentation | 閲覧、状態表示、変更案の確認 |
| application | 読込・補正・保存・復元のユースケース |
| domain | マクロ、装備セット、枠、所持品、参照状態 |
| references / fixes | 純粋な状態判定と補正計画。ファイルI/Oなし |
| adapters / codecs / dictionaries / icons | 原本読取、バイナリ解析、文字列・アイコンの解決 |
| saving | 保存前再検証、限定的なバイト変更、バックアップ、置換、復元 |
| store | アプリ専用の表示名。ゲーム内へメタデータを書かない |

## 判定

「一致」は同じキャラの収納ID・内部位置・種類IDが一致すること。表示上の並び順とは別で、種類IDは個体識別子ではない。オーグメントや個体未確認を一致条件に含めない。

保存位置が異なり、全17収納を取得できていて種類IDが一意ならFix可能。収納家具・金庫も対象とする（外見固定用途を含む）。候補複数・候補なし・取得不足・不正な位置などは自動補正しない。

ゲームの代替検索により、保存位置が異なっていても装備できる場合がある。不一致を即座にゲームでの装備不能とは扱わない。インベントリ保存情報からサーバー側の現在状態や恒久的な個体同一性は断定しない。

## 保存の前提

FF11・PlayOnline終了時のみ。対象ファイルと全収納をSHA-256で再確認し、ドメインで候補を再計算する。収納と位置のバイトだけを変更しMD5を更新。バックアップをflush/fsyncして検証し、同一ディレクトリの一時ファイルから置換する。保存先を全バイト比較し再デコードする。

対象ハンドル解放から置換までの短い競合窓は残るため、保存中にゲームや別のエディタを起動しない。複数ファイルのトランザクションや停電に対する絶対的な永続性は保証しない。復元は保存後ハッシュが一致する場合のみ行う。
