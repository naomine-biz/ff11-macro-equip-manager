# 責務と参照状態

個別編集を追加するための責務分担と移行手順は[個別編集と保存の設計](editing-design.md)を参照する。以下は現在の実装を説明する。

## 責務境界

| 部品 | 責務 |
|---|---|
| ui / presentation | 閲覧、状態表示、変更案の確認 |
| application | 読込・補正・保存・復元のユースケース |
| domain | マクロ、装備セット、枠、所持品、参照状態 |
| references / fixes | 純粋な状態判定と補正計画。ファイルI/Oなし |
| adapters / codecs / dictionaries / icons | 原本読取、バイナリ解析、文字列・アイコンの解決 |
| saving | 保存前再検証、限定的なバイト変更、バックアップ、置換、復元 |
| store | アプリ専用の表示名。ゲーム内へメタデータを書かない |

## 判定

「一致」は同じキャラの収納ID・内部位置・種類IDが一致すること。内部位置は収納内の保存スロットを、種類IDはアイテムの種類を表す。

保存位置が異なり、全17収納を取得できていて種類IDが一意ならFix可能。収納家具・金庫も対象とする（外見固定用途を含む）。候補複数・候補なし・取得不足・不正な位置は保留とする。

ゲームの代替検索により、保存位置が異なっていても装備できる場合がある。照合結果は読み取ったローカルのインベントリ情報に基づく。

## 保存の前提

FF11・PlayOnline終了時のみ。対象ファイルと全収納をSHA-256で再確認し、ドメインで候補を再計算する。収納と位置のバイトだけを変更しMD5を更新。バックアップをflush/fsyncして検証し、同一ディレクトリの一時ファイルから置換する。保存先を全バイト比較し再デコードする。

対象ハンドル解放から置換までの短い競合窓があるため、保存中はゲームや別のエディタを終了した状態に保つ。OS上の置換は1ファイル単位。GUIの保存操作は複数ファイルを扱い、全原本のバックアップ後に順次置換する。途中失敗では今回の書込内容に一致する対象を復元する。一括保存の復元CLIは原本または保存後ハッシュに一致する対象を扱う。旧単一枠CLIの復元は保存後ハッシュとの一致を条件とする。

## マクロと装備セットの参照

macro_linksは読み取り専用のドメインクエリ。application経由でUIに結果を渡す。キャラ内の各マクロ行の先頭にある/equipset・/lockstylesetと1〜200の固定番号を解析する。定型文の解決済みコマンドも扱う。参照番号はコマンド直後から抽出し、末尾のecho、wait、付加テキストから独立して判定する。マクロ構文の妥当性検証は別の責務とする。チャットへの記述、動的番号、範囲外番号は解析対象から除外する。

全16枠がkeepのセットを空とする。remove指定のセットは動作あり、未知動作・未取得セットは要確認として扱う。空判定には16枠の動作を使用する。未参照は読み取れたマクロの対応コマンドから参照がないことを意味し、手入力や外部スクリプトでの利用は対象外。空のセットは未参照一覧とセット側の参照表示から除外する。マクロ側の空セット参照通知は維持する。左の装備セット一覧では空セットの文字をグレーで表示する。

UIはマクロカードと行詳細で空セット参照を通知し、装備セット一覧にマクロ参照なしを表示する。専用の確認画面から対象へ移動できる。この確認機能は読み取り専用とする。

装備セット選択時、右パネルに参照元マクロのブック・パレット・Ctrl/Altキー番号・マクロ名・行番号・コマンドを表示する。空セットでは参照表示を省略する。

マクロ画面のナビゲーションはブック名を親、パレットを子とするツリー。ブックは1つずつ開くアコーディオン表示とし、別のブックを開くと前のブックを閉じる。初期表示と参照一覧からの移動では、対象パレットのブックを開く。全マクロの名前と全行が空のパレットはグレー表示する。全パレットが空のブックもグレー表示する。名前のあるマクロや行に内容のあるマクロは使用中として表示する。

## 編集バッファと責務

| 部品 | 責務 |
|---|---|
| macro_inventory | /equipの解析、候補照合、収納番号の置換案。純粋なドメイン処理 |
| editing | 読込時の基準データと編集データ、変更前後を持つ操作、Undo／Redo。メモリ内で完結 |
| edit_application | ドメインへの委譲、古いFix案の再検証、作業保存成功後の編集状態の更新 |
| draft_store | 作業ファイルの直列化、原本ハッシュの照合、排他・一時ファイル・置換 |
| UI | 状態の表示、入力、差分プレビュー、操作の依頼 |

1つの編集セッションはインストール先の全キャラを扱う。読み取りスナップショットをコピーして基準データと編集データを作り、画面と参照判定は編集データを見る。個別編集・一括Fix・将来のカスケード更新をそれぞれ1操作とする。操作中の1箇所でも前提が崩れていたら、操作全体を中止する。新しい操作は現在位置より先のRedo履歴を置き換える。

装備セットFixも同じ履歴に記録する。Undo／Redoはキャラ横断の操作順に行う。変更のない編集は履歴に追加しない。未変更のTextはraw_hexを保持し、変更したTextはdraft状態で保持する。収納番号Fixの保存アダプターは元バイトへの位置対応を使って番号部分を変更し、60バイト上限とMD5を検証する。任意の本文編集のエンコードは今後の機能とする。

編集内容と履歴は、形式のバージョンを記したJSONへ自動保存する。基準データのファイルパスとSHA-256、全履歴、現在位置を保存する。復元時は読込元との一致を確認して履歴を再適用する。

取得元が変化した場合や履歴の破損時は作業再開を保留し、既存作業ファイルを保持する。この場合は旧作業を保管し、新しく読み込んだデータから編集を始める。差分の選択的な引き継ぎは今後の機能とする。

作業保存は排他ロック・変更検知・一時ファイルのflush/fsync・置換で行う。保存失敗時はメモリ上の編集状態も維持する。複数起動からの上書きを検出する。プロセス強制終了によってlockが残った場合は、全アプリ終了後に該当lockを除去して再開する。

GUIは作業ファイルへの自動保存と、マクロ収納番号Fix・装備セット参照位置補正のゲーム保存プレビューを提供する。Undo／Redoは編集バッファへ反映する。ゲーム保存時には改めて競合検証・バックアップを行う。既存CLIの装備セット保存機能は独立して保持する。

## マクロとインベントリの参照

/equipの部位・装備名・任意の収納番号を解析する。引用符、解決済み定型文、末尾waitを扱う。収納番号0はマイバッグ、1は内部収納ID8、2〜8は内部収納ID10〜16へ変換する。表示名の完全一致で全17収納の候補を検索する。

| 状態 | 条件・対応 |
|---|---|
| 一致 | 指定収納内に候補1つ |
| 収納未指定・Fix可能 | 全収納で候補1つ、装備用収納にある。番号を追加 |
| 収納違い・Fix可能 | 指定収納に候補がなく、全収納で候補1つ、装備用収納にある。番号を変更 |
| 収納未指定・候補複数 | 番号指定なしで複数 |
| 同一収納に候補複数 | 指定収納に複数。使い分けには収納を分ける |
| 別の収納に候補複数 | 指定収納に候補がなく、別の収納に複数 |
| 候補なし | 全収納に該当名なし |
| 装備用収納への移動が必要 | 唯一の候補が金庫などにある |
| 取得不足 | 収納の読取不足、重複位置、不正な位置 |
| 記述を確認 | 部位・収納番号などの構文を解析できない |

部位だけの/equipは装備を外す操作。候補複数は状態と候補位置を示す。収納番号Fixは数字の範囲だけを置換し、未指定なら装備名の直後に追加する。その他の文字列を保持する。適用時に候補を再計算し、プレビューと一致することを確認する。

マクロ・インベントリ参照一覧は初期表示をFix可能な行に絞る。「すべての参照」で全状態へ切り替える。Fix案のないマクロのFixボタンは無効にする。

## マクロ収納番号Fixの保存

macro_savingはバイナリ変換と保存のアダプター。ドメインの候補判定を呼び出し、保存済みスナップショットと編集バッファの差分から現在も一意なFixに一致する行を抽出する。マクロ名や他の行の手編集は作業データに残す。UIは保存する行・前後の文字列・対象ファイル・保留するマクロ編集数を示す。

文字列全体の再エンコードを避け、元の61バイト行をCP932文字と6バイトの定型文トークンに分解して表示位置とバイト位置を対応付ける。数字の範囲を置換、または装備名の直後に番号を挿入する。6バイトトークン内のゼロを保持する。行末はNULを含め61バイト、最大本文60バイト。変更対象の行とヘッダーのMD5を更新し、他のレコード・未知領域を保持する。使用しない行末領域は新しい本文とNULが必要とする範囲だけを上書きする。

保存対象は選択キャラの複数パレットファイル。FF11・PlayOnlineの終了を確認し、対象マクロ・17収納・名前と定型文の辞書を読取ロックしてハッシュを確認する。ディスクからスナップショットを再構築してドメインのFix案と照合する。全原本とreceipt.jsonをゲーム外へflush/fsync付きで保存し、全対象の一時ファイルの作成・検証を終えてから順次置換する。各置換後に全バイト比較とデコードを行う。

途中の例外では、今回の書込後ハッシュが一致する対象を逆順に原本へ復元する。ゲームが起動した場合や別の変更を検出した対象は復旧確認として残す。OSによる複数ファイル一括の原子的置換は提供されないため、強制終了・停電の途中状態はreceipt.jsonと原本を使って復元する。復元CLIは全対象を先に検証し、元の状態または今回の保存後ハッシュと一致するファイルを扱う。

編集セッションは履歴起点baseline、編集結果working、最後のゲーム保存状態savedを保持する。dirtyはsavedとの内容比較で判定する。作業ファイルv2はsavedのソースハッシュを記録し、履歴の各対象の最初のbeforeから履歴起点を復元する。v1作業ファイルも読み込める。保存後も既存履歴を保持するためUndo／Redoと再起動後の履歴再開が可能。Undoで戻した古い収納番号など、現在の一意なFix条件を満たさない変更は今回のゲーム保存対象から保留する。

ゲーム書込前に保存後チェックポイントをpending.jsonへ記録する。書込後は作業ファイルのsavedを更新する。ゲーム保存が完了し作業同期だけが失敗した場合、再起動時にpendingのハッシュと実データを確認して同期を完了する。作業ファイルの別更新や、複数ファイルの部分保存を検出した場合は再開を保留して記録を保持する。復元後はアプリを再起動して再照合する。

## ワードローブの未参照アイテム

wardrobe_usageは編集バッファから逆参照を求める純粋なドメインクエリ。applicationが読取失敗情報を渡し、UIは結果を一覧表示する。選択キャラのワードローブ1〜8（内部ID8、10〜16）を対象とし、内部位置ごとに表示する。

/equipは装備名と指定収納から候補を求める。指定収納に1件なら参照あり、複数なら参照候補あり。収納未指定は同名候補を全体で調べる。指定収納に候補がないときは他収納の同名候補を参照候補として保持する。

装備セットは全セットを対象とする。マクロから呼ばれていないセットや外見固定用も含む。収納・内部位置・種類IDが一致するアイテムを参照ありとし、保存位置がずれている場合は同じ種類IDの候補を参照候補ありとする。変更しない枠と装備を外す枠はアイテム参照を持たない。

両方から参照も候補もない行を未参照として表示する。読取失敗したマクロ・装備セットがある場合、名前未取得、重複位置などは確認保留に分ける。一覧は未参照を初期表示とし、参照候補あり・確認保留に切り替えられる。収納・内部位置・種類ID・アイテム名と根拠を表示し、インベントリの対象へ移動できる。編集・Undo／Redo後に一覧を開くと現在の編集バッファで再判定する。


## 装備セット参照位置の保存

equipment_savingは装備セットの保存アダプター。savedとworkingの意味上の差分を、ドメインのplan_fixesが返す一意な候補と照合する。適用済みの位置補正のみ抽出し、選択キャラのes0〜es9.dat単位にまとめる。セット名・種類ID・アクション・その他のバイトを保持し、収納・位置とチェックサムを更新する。全17収納と対象ファイルのハッシュを確認し、ディスクのデコード結果からも候補を再計算する。

UIはプレビューと明示的な保存操作を担当する。セット番号・名前・枠・アイテム名とID・変更前後の収納と位置・対象ファイル・保留件数を表示する。Editorは別の起動中のアプリによる作業ファイルの更新を確認してから、保存後の状態をpendingに記録する。保存アダプターによる書込みが成功したら、savedを更新する。マクロ保存と共通のチェックポイント処理を使用し、履歴と他の編集を保持する。候補判定はfixes、バイナリ書換はsaving.patch_equipmentに委譲する。

保存時はFF11・PlayOnlineの終了を確認し、全依存ファイルを読取ロックして再照合する。全原本とreceipt.jsonをゲーム外へflush/fsync付きで保存・検証し、全書込用一時ファイルを準備してから順次置換する。各ファイルを全バイト比較・デコードで検証する。

途中失敗は今回の書込内容と一致する対象を逆順に復元する。ゲーム起動や外部変更を検出した場合は復旧記録を保持する。複数ファイルにまたがるOS上の原子的保存はないため、中断からの復元にはrestore_equipment.pyで全バックアップと現状を先に検証する。元データまたは今回の保存結果に一致する対象だけを復元する。

検証は合成したゲームファイルを使用し、複数ファイル保存、バックアップ、対象外バイト維持、古いプレビュー拒否、候補改変拒否、ゲーム起動中の拒否、権限・バックアップ失敗、途中失敗の復元、チェックポイント復旧、再起動後Undo／Redo、GUIからの保存を確認する。


## 個別編集の基盤（段階1）

edit_valuesは意味上の内容比較と構造検証を担当する。EditSessionは編集案の全前提を検証し、コピーへ一括適用して履歴を管理する。派生参照状態と原本情報の違いはdirtyや履歴前提の内容差分に含めない。Editorはセッションを管理し、UIには独立した表示用スナップショットと操作状態を返す。個別入力はprepare_macro_edit経由で変更案を作り、applyで適用する。

保存計画の保留項目はsave_plan.DeferredChangeに対象と理由を持たせ、プレビューに表示する。macro_savingとequipment_savingは既存の補正条件とファイル形式を担当し、共通のfile_transaction.execute_batchに書込みを委譲する。ロックからバックアップ・全ファイルの準備・置換・検証・失敗時復元までを同じ実行器に集約した。対象追加・欠落と構造不正は保存計画の作成時に拒否する。詳細な実装結果と残る範囲はediting-design.mdの段階1実装結果を参照する。

クラス構造、主要メソッドの内部処理、編集と保存の呼出し順は[編集・保存のUML](editing-uml.md)を参照する。
