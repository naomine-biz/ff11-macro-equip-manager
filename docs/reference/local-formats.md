# ローカルファイル形式

本書はファイル形式の調査結果。ユーザー向け動作は[要件](../../requirements.md)、編集・保存の責務は[設計条件](../design-constraints.md)で定める。

調査時点: 2026-10-27。根拠の公開資料は[sources.json](sources.json)。読込時には以下の形式を検証する。未知バイトは元の値を保持する。

## 共通

キャラクターフォルダはインストール先の `USER/<folder-id>`。マクロ・装備セット・所持品ファイルは24バイトのヘッダーを持ち、オフセット8〜23は24バイト以降のMD5。読込時にサイズとMD5を確認する。キャラの表示名はユーザーが登録する。

## マクロ

`mcr.dat`、`mcr1.dat`〜`mcr399.dat` は7624バイト。24バイトヘッダー＋380バイトの20レコード。レコード先頭4バイトの後に61バイト×6行、オフセット370から10バイトの名前。10パレットで1ブック、最大40ブック。20マクロの前半はCtrl、後半はAlt。

ブック名 `mcr.ttl` / `mcr_2.ttl` は344バイト（ヘッダー＋16バイト×20）。文字列はCP932にFF11の定型文トークンが混在する。トークン内部にはNULが含まれることがあるため通常のNUL終端処理より先に解釈する。

## 装備セット

`es0.dat`〜`es9.dat` は1624バイト。ヘッダー＋80バイト×20セット、全200セット。各セットは名前16バイト＋4バイト×16枠。

枠の形式はリトルエンディアン `<BBH>`。第1バイト下位2ビットは動作（0=維持、1=装備、2=外す、3=未解釈）、上位6ビットは収納ID。第2バイトは収納内位置、第3〜4バイトは種類ID。

部位順: main, sub, range, ammo, head, body, hands, legs, feet, neck, waist, ear1, ear2, ring1, ring2, back。

装備位置Fixは選択された収納と位置だけを変更する。名前変更は16バイトの名前領域にCP932を保存し、16バイト未満では直後にNULを置く。16バイト丁度は固定長の全領域を使う。終端以降の元バイト、16枠、他のセット、未知ヘッダーを保持し、本文MD5だけを更新する。

## インベントリ保存情報

17ファイル各4240バイト。先頭2個のuint16は0x0208と4216。0xA3C以降に20バイト×81レコード。レコード内+16が内部位置、+17は未解釈、+18〜19が種類ID。ID 0/65535は空きとして除外。数量やオーグメントはこの実装では取得していない。

| 収納ID | ファイル |
|---|---|
| 0〜9 | is.dat, bs.dat, cl.dat, ti.dat, mb.dat, sb.dat, sk.dat, ca.dat, wr.dat, b2.dat |
| 10〜16 | wr_2.dat〜wr_8.dat |

## 共通ゲームリソース

FTABLE.DATからROMのファイル位置を解決する。アイテムレコードは0x1400バイトで、各バイトを5ビット右回転して読む。アイコンはレコード内のパレット付き32×32ビットマップをPNGへ変換し、メモリ内で表示する。ゲームリソースの抽出物はリポジトリに含めない。

## マクロの手編集保存（2026-10-28）

名前の保存領域は10バイト（S02/S11）、行は61バイト（S02/S11）。本アプリは終端NULを含めず、名前8バイト・行60バイトを保存上限とする。名前8バイトは、S02の8文字制限を踏まえた安全側のアプリ方針であり、領域容量と区別する。S02のEncoding.Defaultによる文字単位の切詰めとS11のバイト切詰めは採用しない。CP932で厳密に変換・再読込照合する。

`FD + 4バイト + FD`は6バイトの定型文。内部NULを終端として扱わない。元フィールドから表示とIDの対応を取り、保持可能な一意のトークンだけ再利用する。変更した文字列とNULだけを置換し、終端後の未使用バイト・レコード先頭4バイト・未変更フィールド・ヘッダー未知領域を保持する。


## 定型文の新規挿入（2026-10-29）

初期対応は`FD 02 01 HH LL FD`。`HH LL`は日本語定型文辞書のキーで、`LL=00`はカテゴリ見出しとして挿入候補から除く。論理DAT ID `0xD8F9`をFTABLEで解決する。`@A`・`@C`・`@J`・`@Y`の名称参照は既存のローカル読込処理で解決する。根拠はS03/S07/S14および既存デコーダ。アイテムIDを上位HH・下位LLに分け、両方非ゼロなら`07 01 HH LL`、HH=00なら`09 01 FF LL`、LL=00なら`0A 01 HH FF`で挿入する。既存のresolve_tokenの逆変換として実装し、ゼロ境界と同名別IDを合成データで検証する。

編集値は表示範囲と4バイトの識別値を保持する。保存時は選択IDの名称を辞書と照合して6バイトのトークンに変換する。元フィールドを使う既存の変換経路も維持する。

日本語定型文の通常レコードでは名称の長さ・名称に続いて、読みの長さ（1バイト）と読みのCP932文字列を持つ。読みが空の項目もある。読みは名前と別に保持し、`@C`等の名称参照を解決した後も元の定型文キーに対応させる。2026-10-29のローカル辞書確認では「挑発／チョウハツ」「火門の計／カモンノケイ」を確認。

## 装備可能部位と枠の個別保存

アイテムDATは0x1400バイト単位で右5ビット回転して復号する。種類IDが0x2800以上0x7000未満の装備レコードでは+0x12のuint16が装備可能部位のビット列。bit 0〜15は装備セットの部位順に対応する。範囲外の一般アイテムを同じオフセットで解釈しない。読込結果はequip_slotsとして扱い、取得元ファイルを保存前検証に使う。根拠はsources.jsonのS03。2026-10-29の読取調査では既存6,388枠に部位欠落・不一致なし。

各枠の個別保存では、equipは収納番号を上位6ビット、動作1を下位2ビットとし、内部位置と種類IDを更新する。keep/removeは動作の下位2ビットのみ0/2へ変更し、意味を持たない残りの原本バイトを保持する。デコードした参照値はNone。対象枠以外と未知領域は保持し、本文MD5を更新する。
