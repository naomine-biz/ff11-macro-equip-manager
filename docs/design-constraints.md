# 設計上の制約の正本

[要件](../requirements.md)を満たすための責務・依存方向・値の保持元・更新経路を定める。具体的な型・クラス・メソッドはコードで管理する。設計条件IDは維持する。

本書は目標とする制約を含む。現在の実装・検証範囲は[対応表](requirements-traceability.md)、文書の更新手順は[文書の管理](README.md)を参照する。

## D-01 責務と依存方向

対応: EQ-004、EDIT-001〜006、SAVE-001〜006。

| 担当 | 責務 |
|---|---|
| ドメイン・編集操作 | 値の制約、参照状態、候補判定、変更案の作成。I/O・GUI・バイナリ配置に依存しない |
| 編集セッション | 変更案の前提検証、一括適用、Undo/Redo、履歴と未保存差分の管理 |
| アプリケーション処理 | UIの要求を受け、ドメイン・セッション・作業保存・ゲーム保存を連携させる |
| 保存計画 | 保存済み値と作業値から保存範囲・保留理由・依存資料を決め、形式変換へ渡す |
| ファイル処理 | 読込・形式変換・原本保持・排他・バックアップ・書込・検証・復旧 |
| 作業ストア | アプリ専用の編集状態・履歴を永続化し、版と競合を検証する |
| UI | 入力・プレビュー・結果表示と、アプリケーション処理への依頼 |

- 参照判定とFix条件はドメインを保持元とし、UI・保存処理に同じ規則を再実装しない。保存時の再確認もドメインを呼ぶ。
- 編集状態の更新はアプリケーション処理から編集セッションへ集める。読み取り用に渡した値から内部セッションを変更できない構造にする。
- 純粋な参照クエリはUIから利用できる。ゲームへの書込はファイル処理へ集約する。
- 待機表示の設定・解除はUIの共通処理へ集約する。各編集操作はこの処理を呼び、ドメインや編集セッションへ表示の責務を持ち込まない。

## D-02 値の保持元と比較

対応: EQ-004、EDIT-002〜004、SAVE-006。

- 装備セットが枠の値を保持する。参照検索用のビューはその値から生成する。部位と固定16枠の順序を対応させる。
- 枠の参照状態はドメインで算出して枠の属性として扱い、編集・Undo/Redo後に再評価する。
- baselineは履歴起点、workingは表示・判定・編集の対象、savedは保存成功を確認した状態。保存で履歴起点を変更せず、保存した範囲だけsavedを更新する。
- dirtyと変更前提は対象キー集合と意味上の値で比較する。原本バイト・読込情報・派生状態は比較から分ける。定型文の識別情報は原本の付帯情報と区別して保持する。
- 変更案は対象キーと変更前後の値を持つ。セッションは存在・重複・型・構造・前提値を検証し、無変更案も検証を通す。
- 未変更の未知値と原本情報を保持する。新規入力の妥当性検証と、記録済みの値へ戻すUndoを分ける。

## D-03 作業状態の確定

対応: EDIT-002〜005。

次状態を独立した編集状態として作り、作業ファイルへの保存成功後にアプリ内部の状態を更新する。失敗時は現在のworking・履歴・cursorを維持する。編集セッションは未変更部分を共有できるが、所有する値を直接変更・公開しない。受け入れた値と外部へ返す値を内部状態から分離し、変更は対象の置換で行う。ドメインモデルは共有・履歴管理の方式に依存しない。

作業ストアは版・更新競合・読込元・履歴前提を検証する。原本の読込情報と編集履歴を対応付け、破損・競合した作業を保管できる構造にする。ゲームへの保存と作業の自動保存は別経路にする。

## D-04 編集案と保存案の境界

対応: SAVE-001〜004、FUT-001。

- 編集案は意味上の値を扱う。ファイルパス・オフセット・置換バイトは保存計画とファイル処理で扱う。
- 保存案は対象・差分・保留理由・原本と依存資料の指紋を持つ。形式変換は未編集部分・未知領域を保持できる原本情報を受け取る。
- 依存資料は操作ごとに定める。名前変更へ持ち物一意性などのFix専用条件を広げない。
- カスケードの直接変更と参照更新は依存グループとして表し、適用・Undo/Redo・保存で一括性を維持する。
- 文字列の意味上の妥当性と、CP932・バイト上限・トークン変換などの形式上の保存可否を分ける。編集Textには元フィールドのバイトを保持し、形式変換で定型文の識別に使う。表示名から辞書を逆引きしてIDを推測しない。保存案にはフィールド位置と変換根拠を保持し、保存直前に再生成して比較する。

## D-05 共通書込みと保存済み状態

対応: SAVE-002〜006、SAFE-001。

ゲームへの書込みは共通実行処理へ集約し、SAVE-002〜005の検証・バックアップ・復旧条件を実行する。形式ごとの処理は変換と検証を担当する。

書込前にpendingを記録し、検証済みの保存結果を得てからsavedを更新する。ゲーム保存と作業同期の成否を区別し、再起動時に照合・復旧できる情報を保持する。復旧未完了時の操作停止はアプリケーション処理で一貫して適用する。

## D-08 実行トレース

UI操作・アプリケーション処理・ファイル処理の境界を共通の計測処理で記録する。操作IDと親子の区間ID、処理名、開始日時、単調時計で測った所要時間、成否を持つ。親区間の時間は子区間を含む。本文・キャラ名・ファイルパス・例外メッセージは記録しない。ログは容量制限と世代管理を行いGit対象外とする。ログ出力の失敗で操作の成否を変えない。ドメインは計測基盤に依存しない。
